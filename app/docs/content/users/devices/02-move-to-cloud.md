Move to cloud when local-only storage is no longer an acceptable risk.

The usual reasons are:

- You need account recovery.
- You need a safer path between devices.
- You are storing enough data that losing browser state would be expensive.
- You want billing-backed storage choices instead of a disposable local trial.

## What Changes

Your Space remains a Space. The app still opens the same kind of primary surface. What changes is the account and provider path behind the session.

Do not delete the old local session until the cloud-backed session opens the Space and shows the data you expected.

## Safe Order

1. Finish backup and lock setup for the current session.
2. Start the cloud upgrade or sign-in flow.
3. Open the Space from the cloud-backed session.
4. Verify at least one file or object.
5. Keep the old session until you have restarted the app and verified again.

If you operate your own runtime or storage policy, read [Storage Modes](/docs/self-hosters/storage/storage-modes).
