Spacewave is a local-first workspace. A **Space** is the container you open from the app. It can hold files, a Drive, a Git repository, a Canvas, or other typed objects.

The fastest useful path is:

1. Open Spacewave.
2. Choose **Create a Drive** if you want folders and files, or **Create an Empty Space** if you want to choose objects later.
3. Add or upload a small file.
4. Open the Space again from the session dashboard to confirm the file is still there.
5. Add backup and lock setup before you put important data in the session.

Spacewave can run without a cloud account. A local session stores state on this device. A cloud account adds Spacewave Cloud account identity and storage choices, but it does not turn every Space into a remote-only workspace.

## What to Read First

If you are new, read [Create Your First Space](/docs/users/start/create-your-first-space), then [Drive and Files](/docs/users/files/drive-and-files).

If you already have a local session and want to protect it, read [Backup and Lock Setup](/docs/users/accounts/backup-and-lock-setup).

If you want another device to see the same account, read [Link Devices](/docs/users/devices/link-devices).

If you prefer terminal workflows, read [Command Line Basics](/docs/users/cli/command-line-basics).

## What Not to Assume

The release-visible Quickstarts are account, pairing, empty Space, Drive, Git repository, and Canvas. Notebook, Docs, Blog, Chat, V86, and Forge Quickstarts are development or experimental surfaces unless your build exposes them.

Public docs and in-Space documentation objects are different. The docs you are reading are bundled app documentation. A Space-native docs object is an object inside one of your Spaces.
