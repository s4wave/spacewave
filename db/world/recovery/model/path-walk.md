The count reads an isolated SQLite capture below Flowgraphs, before a Space can load. It opens neither a Volume nor a provider for input.

1. `sqlite.OpenImmutable` checks one file and two journal names, then opens `mode=ro&immutable=1`. One connection has a 2 MiB page cache and mmap disabled. The interface contains Get, Next and Close. SQL changes only connection-local pragmas. The caller supplies a frozen checkpointed capture; a WAL or hot rollback journal is rejected.
2. `Immutable.Next` seeks an indexed primary key and reads both column lengths before allocating either. A nil continuation selects the first key explicitly, including an empty BLOB key. Each call makes two indexed reads and copies one bounded record. Every row closes before scratch processing. `Get` bounds the value before reading it. Keys/values over the record limit pause the run.
3. `openScratch` uses the existing SQLite KV store with FULL synchronous commits, a 2 MiB cache per connection, four connections, mmap disabled and FILE temporary storage. A single table holds disjoint index prefixes. Open/resume reads a schema and one report; it loads neither free-page IDs nor the inventory. SQLite's native pager manages disk indexes. Source readers have their own bounded pools. Its checkpointer serves only the separate scratch file. Before a writer opens, the scanner canonicalizes the scratch target and rejects source-inode aliases through the main file, WAL, SHM, rollback journal and keyed lease file. URI-ambiguous scratch names reject. An existing cross-process keyed lease excludes another count while allowing saved report reads.
4. The scratch transaction composes the existing KV methods. Every failed Get/cursor operation is retained on the transaction and prevents commit. Successive steps share one write transaction, the batch, and each step saves the whole result beside its rows; the batch commits at every phase, table or pack boundary and after at most 4096 steps or 8 MiB of rows. A failed step discards the batch and a crash loses it, so the scan resumes from the last committed step exactly as a fresh run would, and one fsync covers up to 4096 steps. Each keyset cursor closes its native iterator before returning one copied row. No cursor or SQL row survives across a source read. Normal source records are copied to the data prefix; source metadata, locations and roots use separate prefixes.
5. Inventory copies one physical occurrence per step and records its cursor with the distinct-block/location counts. Content bytes are checked against the full native reference. Duplicate source table declarations reject; duplicate records in different tables retain two locations and one content identity. Native root metadata is read directly. Stored child lists, including inherited unverified lists, never supply reachability proof. A table without a version key is format 0, whose block keys are base58 text; formats 1 through 6 keep named roots in legacy graph records the count does not read, so they mark reachability incomplete and name the gap.
6. After the tables, inventory reads each declared pack directory in name order, one pack per batch, with the directory index and last pack name as its cursor. Choosing the next name streams the directory in batches of 256, so memory stays bounded and a directory of F packs costs O(F^2) directory entries in all. Each pack opens `O_RDONLY` behind a type that exposes only ReadAt and Close, so no write, truncate, rename, finalize or remove is reachable; the store's own `packahead.Open` truncates and finalizes open logs and is never called. A finalized local or remote pack reads through `packfile.ScanPack`: the index tail in at most three reads, then one value at a time, bounded before allocation. An open local log, or a local pack whose index does not read, reads through `packahead.ScanRecords`: each batch record is bounded, its value checksum is streamed in 1 MiB chunks before any value is trusted, and the scan stops at the first invalid record. Bytes past it are counted as retained unread tail bytes and named as a gap. Every value is checked against its key with `packfile.DecodeBlockValue`; a corrupt value is counted and skipped. A pack whose size, mtime or inode changed across its read fails the step; each directory's identity is part of the input identity. Links and other non-regular entries are never followed and are named as a gap; a pack neither reader accepts is counted unreadable and named.
7. Typed decoding uses native World, tree, Object, changelog and body constructors. Node identity includes the full reference, normalized bucket/transform context, constructor, expected tree key and chunk length; World provenance and the context's incidental root pointer are excluded. Work and visited facts live on disk. A decoded block contributes at most its bounded outgoing references. Unsupported constructors/transforms and missing bytes mark partial closures.
8. Per-World membership uses the existing standalone native WorldState constructor on scratch only, avoiding Engine transaction wrapper handles. One ordered object is read per step, with its matching metadata key and historical graph type. The type lookup admits at most two matching native quads; ambiguous types remain partial. Native readers close before the scratch writer opens. Its normalized exact version and World provenance are independent disk relations. Shared tree/body decoding remains one operation per interpretation. A graph/type failure preserves known object metadata as a partial version. Changelog Object aliases connect to matching captured typed body evidence or remain unknown. Differing body constructors for the same exact metadata mark both version and alias ambiguous, independently of declared World order; the scanner never picks the last World as a winner.
9. Bad closures propagate through reverse edges in slices of at most 128. Reachability and current-World provenance likewise follow at most 128 edges per transaction, with active-node/edge continuation on disk. Root alias lookup is sliced at 128. Native roots carry hashes and their native key supplies the bucket. Inventory uses the native key parser and requires a declared World in that same bucket; a root without a declared World constructor/transform context keeps non-reachability unknown even when its bytes have another known interpretation. Node-local delete facts are bounded by one decoded block. All frontiers and visited relations remain on disk. Missing current-root descendants are separate holes; an incomplete held root makes unreached bytes unknown rather than proven orphaned.
10. Causal validation checks native operation/checkpoint structure and hash identity; matching acceptance/refusal must have the same preceding World and exact operation. A normalized version must appear after acceptance, differ before acceptance, and be absent after refusal and at checkpoint cover. Cover requires the exact author, nonce and hash, and carries the refused state. Later author heads without a surviving author-chain proof remain unknown. This first native interpreter accepts targets at the first replay position only, where the preceding full bucket/transform context survives; later prefixes remain an explicit gap. Versions at observed delete keys are a separate subset; native delete evidence names a key, not each older exact version, and cannot earn refusal confirmation.
11. Final passes read one version or physical record per step. Summary rendering reads one bounded Result and never rescans. ReadResult opens scratch only, so a report remains readable without its capture. Input identity includes the manifest, interpretation registry ID, physical device/inode and size/mode/mtime/ctime; each work/final boundary rechecks it. Ordinary OS reads may update access time; the scanner neither promises nor attempts to restore atime.

Let P be physical occurrences, B distinct hashes, N interpreted nodes, E edges, W declared Worlds (at most 64), V exact versions and M memberships. Inventory is O(P log B + bytes + F^2) for F packs in one directory, union interpretation/closure is O((N+E) log N + decoded bytes), membership is O(M log A) indexed World work, and final counts are O((B+V) log(B+V)). Per-World provenance is O(W*E) in the worst case and remains disk-backed; the body decoder and closure graph are shared. Memory depends on the fixed page/connection budgets and admitted record/context limits, never on frontier width, free-page count, roots discovered or stored block count. There is no serving writer, serving lock or live-disk wait.

Covered: ordinary SQLite Volume key/value records in formats 0 through 12 (formats 0 through 6 without legacy named roots), all declared table locations, declared local pack log directories (open logs and finalized packs) and declared retained remote pack directories, and captured native roots/Worlds. Not covered, each named in the result: s4db, which has no read-only capture reader; paylog BlockDomain values, whose index opener replays the whole index into memory and starts new segments; remote catalogs; and packs outside the declared directories, including uncataloged ones. Unknown constructor, transform and causal history classes remain explicit in the result. Only empty transforms and bounded native gzip/block encryption chains are admitted, with at most eight steps. Native Snappy and LZ4 decoders remain unsupported before any allocation or snapshot opener can reach them. Unbound detection probes separate plain Object records only. It does not probe every declared transform context or discover detached World, IAVL, Okra or changelog roots. Unassigned bytes remain evidence; zero structural candidates cannot certify their absence. Wholly absent versions cannot be counted.
